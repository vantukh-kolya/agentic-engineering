# 0001 — Serve the session index at the root with a query limit

- **Status:** Accepted
- **Date:** 2026-11-10
- **Deciders:** maintainer; вибір 1 під час design

## Context

Головна сторінка зараз показує заглушку. Ухвалений зріз session-index додає лише перелік сесій, а графіки й аналітика залишаються наступним роботам. Треба визначити адресу переліку й спосіб зберегти обрану кількість рядків у посиланні.

## Decision drivers

- Spec US-01 і US-03: відкрити спільний перелік і керувати кількістю рядків.
- Spec AC-04 і AC-05: типовий ліміт 50, допустимі значення 1–1000, помилкове введення відхиляється явно.
- Spec AC-15: використовувати наявну оболонку й навігацію.
- SAD §2: серверний HTML, без нового машинного інтерфейсу чи браузерного стану індексу.

## Considered options

1. **Перелік на `/`, ліміт у `?limit=…`.** Замінити заглушку головної; відсутній параметр означає 50 рядків.
2. **Перелік на `/sessions`, ліміт у `?limit=…`.** Відокремити його від головної та додати пункт навігації, залишивши місце для майбутнього дашборду.

## Decision outcome

**Chosen:** варіант 1. `/` віддає індекс із типовим лімітом 50, `/?limit=100` — зі 100 рядками. Власник обрав цей варіант, щоб перелік був першою корисною сторінкою на місці поточної заглушки. Значення `limit` перевіряється за граматикою spec §6; це рішення не змінює меж чи правил сортування.

## Consequences

**Positive**
- Перелік доступний одразу після відкриття дашборду.
- Адреса з лімітом придатна для закладки й повторного відкриття.
- Використовується наявний пункт навігації `/` без додаткової сторінки.

**Negative**
- Якщо майбутня аналітика займе головну, адресу переліку потрібно буде переглянути разом із посиланнями й тестами.
- Параметр адреси є недовіреним введенням; треба розрізняти його відсутність, порожнє й повторене значення.

**Neutral**
- Оновлення відбувається новим відкриттям чи перезавантаженням сторінки, відповідно до специфікації.
- `/api/health` зберігає наявну поведінку; JSON API індексу не додається.
