# 0002 — Return complete metadata before presentation selection

- **Status:** Accepted
- **Date:** 2026-11-10
- **Deciders:** maintainer; вибір 1 під час design

## Context

Адаптер Claude Code зараз лише обчислює шляхи й реєструє джерело. Індекс уперше додає файловий обхід; маршрут має перевіряти ліміт і формувати серверну сторінку. Потрібно визначити, чи повертає читач усі отримані метадані, чи вже відсортований та обмежений перелік.

## Decision drivers

- Spec AC-04: глобальне сортування перед застосуванням ліміту й точна кількість доступних сесій.
- Spec AC-08–AC-10: окремі лічильники пропусків і збереження вже отриманих рядків.
- Spec AC-13 та §6: тільки метадані, без читання журналів, кешу й власного сховища.
- SAD §1: точність і чесний частковий результат мають перевірятися незалежно від HTML.
- Наявна будова: адаптери в `lib/`, маршрут у `server.js`, чисті функції HTML у `views/`.

## Considered options

1. **Читач збирає метадані, маршрут сортує й обмежує.** Адаптер повертає всі доступні рядки й відомості про пропуски; правила вибору видимих рядків застосовуються поза файловим обходом.
2. **Читач одразу готує обмежений перелік.** Адаптер приймає ліміт і повертає відсортовані видимі рядки з підсумками; маршрут коротший, але правила показу входять до контракту адаптера.

## Decision outcome

**Chosen:** варіант 1, підтверджений власником. `listSessions()` адаптера повертає всі зібрані метадані та діагностику повноти. Маршрут перевіряє `limit` до запуску обходу, сортує доступні рядки за mtime, початковим ім'ям теки проєкту та ID, після чого застосовує ліміт. HTML-шар отримує готову модель відображення й не звертається до диска.

Отримання адаптера відбувається через наявний `getSource('claude')`; реєстрація й імпорт адаптера зберігаються. Друге джерело й новий універсальний сервісний шар не додаються.

## Consequences

**Positive**
- Файловий обхід можна перевіряти окремо від сортування, ліміту та HTML.
- Результат читача зберігає рядки, отримані до подальшої помилки, незалежно від видимого ліміту.
- Контракт адаптера не містить налаштувань сторінки.

**Negative**
- Усі доступні метадані передаються між модулями в пам'яті процесу, навіть якщо показано лише 50 рядків.
- Маршрут відповідає за сортування й лічильники відображення, тому він складніший за варіант 2.

**Neutral**
- Обидва варіанти потребують обходу всіх доступних метаданих для вибору найсвіжіших сесій і точного підрахунку доступних.
- Повне сортування використовує O(N log N) порівнянь і O(N) пам'яті для рядків. Обіцянка затримки не вводиться; OQ-01 залишається відкритим до tasks.
- Це внутрішній синхронний контракт ESM-функцій, без нового мережевого інтерфейсу чи персистентної схеми.
