# Performance check — session-index, OQ-01

Вимірювання виконано після T6 на реалізованому індексі, до приймання. Кандидат runtime: `9a4d5a6`. Наступні T7/T8 додали перевірки та CSS; код обходу/сортування/рендерингу HTML, який вимірювався, не змінювався. Size `S`, route `standard`.

## Method

- Лише власні тимчасові синтетичні дерева: 60/1000/10000 звичайних основних JSONL у 3/20/100 проєктах. Кожний файл містить 9 синтетичних байтів; runtime індексу їх не відкриває. Вкладені файли не використовувалися в цьому вимірюванні.
- Запуск через тимчасові Node-скрипти `/private/tmp/session-index-bench.mjs` та `/private/tmp/session-index-bench-request.mjs`, не npm start і не особисте джерело. Дочірній процес імпортує test/helpers.js, явно задає CLAUDE_HOME на дерево й викликає startServer(), який слухає вільний порт тільки 127.0.0.1.
- Для кожного обсягу створено **20 нових Node-процесів**. У кожному — 1 перший і 5 наступних послідовних GET `/` з типовим limit=50. Статус кожного запиту 200, тіло повністю прочитано до зупинки таймера.
- Метрика: wall-clock `performance.now()` від початку fetch до отримання повного HTML. Запуск процесу, імпорт модулів і старт слухача в затримку запиту не входять. Клієнт і сервер живуть в одному процесі, тому синхронний обхід теж входить у замір fetch.
- p95 — nearest rank, елемент `ceil(0.95*n)-1` у відсортованих вибірках. На кожний обсяг: 20 перших + 100 повторних запитів. Без паралельного навантаження, кешу індексу й читання JSONL.
- Дисковий/файловий кеш ОС **не очищався**; перший запит нового процесу не означає холодний диск. Це локальний синтетичний замір HTTP, не вимірювання завантаження браузера чи тест багатокористувацької пропускної здатності.
- Тимчасові дерева й власні сервери прибрані після замірів.

- Node: `v26.13.0`; ОС: `darwin 24.6.0`, архітектура `arm64`.
- CPU: Apple M1 Pro; RAM: 16 GiB.

## Decision pending

OQ-01 **залишається відкритим**: maintainer ще не погодив допустиму затримку й обсяг. Поставлено питання про локальну ціль p95 ≤250 мс для перших і повторних запитів при 10000 сесіях/100 проєктах у наведеному середовищі. Пропозиція не є рішенням, мовчання не є згодою.

Після рішення потрібно зафіксувати числову ціль у spec §6/§8 і узгодити конкретний load-сценарій за inline Test plan. До того числової гарантії немає. Реалізація задач і ці заміри не замінюють незалежне рев'ю та приймання фічі.
